# vision

`lain.` is a local layer that keeps projects, tools, models, memory, and development workflow together.

It should feel less like an app and more like something that quietly lives on the machine and understands what is happening.

## the central idea

Lain should not merely answer what the user is asking.

**Lain should understand what the user is doing.**

That means maintaining an explicit operating picture of the current environment:

- who Lain is
- what the user is working on
- what the current objective is
- what has already been completed
- what is broken
- what is locked
- what Lain is allowed to touch
- what remains unknown
- what should happen next

## principles

- local first
- simple on the surface
- useful before impressive
- reversible changes
- visible state
- persistent but structured memory
- explicit authority
- project boundaries
- decision history
- evidence over assumption
- model independence
- no unnecessary cloud dependency
- automation should save time, not create more work

## memory

Memory should preserve more than facts.

Lain should retain useful project history, preferences, decisions, events, skills, and relationships while keeping provenance visible and avoiding accidental permanence for arbitrary conversation.

## behavior

Lain should have recognizable behavior without requiring a theatrical personality.

It should:

- know when to observe instead of act
- know when approval is required
- preserve locked systems
- remember why important choices were made
- admit when evidence is insufficient
- use the smallest safe change
- verify meaningful work
- keep work resumable

## modes

Lain should expose its authority clearly:

- **OBSERVE** — inspect only
- **ASSIST** — investigate and propose
- **EXECUTE** — perform authorized work

## long-term direction

The end state is not a chatbot with more tools.

It is a personal local computing environment with a coherent brain:

```text
projects
   +
tools
   +
models
   +
memory
   +
workflow
   +
system state
   ↓
  lain.
```

The interface can remain small. The system underneath does not have to.
