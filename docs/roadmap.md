# roadmap

This roadmap describes the direction of `lain.` as the system grows from a useful local development layer into a personal computing environment.

## foundation

- [x] repository and package foundation
- [x] local project discovery and registry
- [x] live project inspection
- [x] configurable local model backend
- [x] deterministic task routing
- [x] project-aware development workspace binding
- [x] controlled tool execution
- [x] authoritative execution facts

## operating picture

- [ ] explicit active-project state
- [ ] project lifecycle state: active / paused / archived / experimental
- [ ] visible authority mode: OBSERVE / ASSIST / EXECUTE
- [ ] mission state and resumable work
- [ ] project constitutions and locked systems

## memory

- [ ] structured memory types
- [ ] decision history
- [ ] event timeline
- [ ] provenance for stored context
- [ ] "why?" lookup across decisions and project history
- [ ] controlled brain-dump ingestion

## reliability

- [ ] checkpoint system
- [ ] forensic debugging workflow
- [ ] stronger verification records
- [ ] explicit uncertainty handling
- [ ] project-aware change boundaries

## environment

- [ ] broader system inspection
- [ ] Git workflows
- [ ] Roblox Studio integration
- [ ] project watching
- [ ] useful process and configuration events

## interface

- [ ] project switch command
- [ ] "what changed?" session summary
- [ ] operating-picture dashboard
- [ ] mission view
- [ ] history and timeline view
- [ ] desktop interface when the underlying system is ready

## later

- [ ] automatic model selection
- [ ] sandboxing
- [ ] project indexing
- [ ] telemetry
- [ ] broader integrations

The roadmap is intentionally subordinate to the architecture. A feature should not be added merely because it looks impressive; it should strengthen Lain's ability to understand, operate, explain, and preserve the user's working environment.
